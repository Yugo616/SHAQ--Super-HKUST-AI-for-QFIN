# SHAQ desktop reliability and flat interface

## User intent

Deliver a dependable daily research desktop with the existing two methods. Necessary free evidence must reach its applicable analysis. Decisions completed before the exchange's actual regular-session open may participate in the existing local simulation. A failed stock must not discard successful research or consume unnecessary later calls. The desktop should feel immediate and visually simple, following the restrained sidebar and flat surfaces of ChatGPT's desktop app. Publish the accumulated local fixes consistently for Windows x64, macOS Apple Silicon and macOS Intel after native acceptance.

The user explicitly requested immediate implementation and cross-platform synchronization on 2026-10-13. Their clarification limits data work to necessary, useful free sources suited to this system. Existing methods, model choices, account rules, preserved records and simulation identities remain authoritative. This work does not authorize broker orders, paid data purchases or extra prediction runs.

## Current findings

- The local citation-recovery and candidate-isolation repair is a saved, uncommitted change; it must be included intact.
- Timing already uses `market_session().market_open` with a strict earlier-than comparison. Preserve it and verify the account consumer rather than restore older fixed cutoffs.
- Earnings calendar evidence can be routed to the event task but skipped because the collector labels the record as market evidence. Calendar entries express scheduled event risk, not a directional realized catalyst.
- A candidate excluded after an early domain failure still receives later domain calls. The existing regression covers a failure in the last domain and misses this waste.
- Desktop activity is polled every ten seconds, and progress rendering replaces whole sections including progress bars. Elapsed time also depends on those polls.
- Software release discovery currently depends on opting into automatic installation. The header always shows an update button, even with no available update.
- Windows's last release failure was a fixture worker/file-lock cleanup race. The tested bounded-wait and worker-drain correction must accompany the public source. A workflow success that only stages artifacts is not a native build.

## Selected approach

Retain the existing Python/pywebview application and native updater. Introduce a small desktop notification layer and update persistent DOM nodes. Redesign the actual three desktop surfaces and existing dialogs with shared neutral styling. A framework rewrite adds dependency and packaging risk without helping the user's task; changing only colors would leave the interaction defects intact.

## Evidence and execution

1. Route earnings calendars to event analysis for relevant symbols. Retain source timing, provenance and calendar-only semantics. Broad benchmark context alone must not manufacture a company event.
2. Audit source-to-task coverage from stored evidence and show useful availability distinctions: available, partial, no event, unavailable, provider failure. Do not promise free sources contain full depth or options opening/closing-side information.
3. Keep the actual-open eligibility policy and existing exact-minute/account requirements. A timely empty result is valid; a late result remains research. Missing execution prices never produce invented fills.
4. Preserve bounded transport/citation retries, shared-failure admission and exact cached requests. For format-3 isolated execution, once a stock is excluded, skip its remaining fresh calls in that pass and retain its existing successes for recovery. Healthy stocks continue. Improve concurrency only within the saved model profile limits and without changing old batch identities.
5. Recovery continues from saved original evidence; published predictions are immutable. Automatic recovery must be bounded and distinguish task interruption from authentication, model identity or shared integrity failures.

## Desktop behavior

- Use the navigation labels 运行分析、修改方法、查看结果. Use a compact neutral sidebar, flat list rows, subtle dividers, system fonts and one dominant action.
- The run page puts the selected methods/model and the current state first. Automatic scheduling and technical details are secondary disclosures. The active job shows a real count and current tasks; terminal jobs stay still.
- The editor uses a stable module list and document area. Result views retain balances, curves, stock directions and net profit, with clear late-research labeling and existing account identities.
- Backend activity changes notify the webview promptly; the UI applies only changed values. It does not periodically reload or reconstruct the page. External scheduler jobs must also be discovered. A short filesystem observation loop may exist behind this notification boundary.
- A one-second local clock updates elapsed/waiting text in place. It never increments completed work or interpolates a model's unknown progress. Text selection, focus, scroll, expanded reports and draft input survive updates.
- Idle notifications do not reindex immutable history. A terminal transition may refresh saved results once. Temporary notification failure keeps the last valid screen and reconnects without starting analysis.
- Closing the window stops and drains its notification workers without stopping independent research. Fixture shutdown drains those workers before deleting temporary files, including on Windows.

## Update behavior

- Discover releases automatically after the first successful desktop load and at the existing configured release-check interval. This is independent of the automatic download/install preference.
- Hide the compact circular header button unless a newer compatible release is verified, downloading, ready, or has a retryable download failure for a known target.
- The button uses a download icon, real download progress, then a restart affordance. Expose accessible names and version information. Retain manual checks and update preferences in settings.
- An update does not interrupt active work, bypass unsaved-draft handling or silently enable automatic installation. Network failure must not present a fabricated available release.

## Verification and release

- Reproduce semantic failures before fixes; test real state transitions, not source-string snapshots where behavior can be exercised.
- Run the relevant offline suite, then the complete suite and eight method/Skill validations. Verify the three native pages and stable node/focus behavior in the actual desktop with isolated fixtures.
- Retain the exact Windows fixture cleanup fix. Run inexpensive platform-independent regressions before dispatching native builds.
- Prepare a clean public source ancestry from the published runtime baseline plus precise repairs. Do not publish the auxiliary release-helper branch or local research/credentials.
- Use a target version greater than the installed 0.7.11 so the installed updater can discover it. Freeze one source commit for Windows x64, macOS ARM64 and macOS x64.
- Keep successful native artifacts. A platform-only failure retries that platform; shared source changes invalidate only the affected evidence. Publish only after matching source/method identities, installation, GUI, update, data preservation and payload checks pass.
- Distinguish implementation, tests, local installation, native-platform acceptance and public release in the final report. External providers and model responses cannot be guaranteed never to fail.
